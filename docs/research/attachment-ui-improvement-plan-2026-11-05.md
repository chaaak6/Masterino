# Masterino 图片与附件 UI 改进方案

本轮目标是统一首页、助理及项目对话中的图片和文件展示，前置每条消息最多十张图片的限制，并针对已确认的 Web 10MiB 上传链路限制、格式解析限制提供准确说明与客户端下载引导。保留 App 本地附件与 Web 上传的现有分流，不改变解析器、存储、模型输入图、历史图片策略或服务端限制。

完整方案已合并 10MiB 截断核查：限制来自 Next.js Proxy 的请求体缓冲，超限不一定返回 413，也可能在上传完整性校验时返回 400。当前只形成方案和测试文档，尚未实施产品变更。

## 1 结论与范围

| 本轮实施范围 | 后续独立评估 |
| --- | --- |
| 十张图片的添加与发送前校验；Web 当前普通上传链路的单文件 10MiB 前置校验；统一状态展示；图片缩略图与消息网格；单层多图预览；413 与截断相关 400 的原因及恢复操作；复用现有 CDN 下载入口 | 模型输入图缩放和压缩、OCR、语义摘要、图片 token 算法、历史图片重读、解析器新增格式、提高服务端容量、修改 Proxy matcher 或上传协议 |

“只改 UI”包含为实现十张限制所需的客户端校验，以及错误到文案、按钮和弹层的映射，不等于只修改 CSS。不更改模型请求、附件来源及解析成功判定。UI 缩略图可以缩小显示，但不能替换发送原图。不得将下载客户端宣传为无限容量或任意格式必定成功。

### 10MiB 限制的含义与复现

Next.js 使用 Proxy 时会为 Proxy 与后续路由缓冲请求体，默认上限为 **10MiB，即 10,485,760 字节**。超过后记录警告并继续处理部分请求体，框架本身不自动向客户端返回错误。[官方说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize)

在仓库实际安装的 Next.js 16.2.9 上直接调用 `getCloneableBody`，消费克隆流、执行 `finalize()` 后再读取路由可见流，得到：

| 原始请求体字节数 | 路由可见字节数，64KiB 分块 | 结果 |
| ---: | ---: | --- |
| 10,485,759 | 10,485,759 | 完整，无超限警告 |
| 10,485,760 | 10,485,760 | 完整，无超限警告 |
| 10,485,761 | 10,485,760 | 截断，有超限警告 |
| 11,534,336 | 10,485,760 | 截断，有超限警告 |

跨界的整个 chunk 会被舍弃，改变分块后实收还可能略少于 10MiB。普通附件 XHR 每次 PUT 一个文件的原始 ArrayBuffer，因此这一链路可按单文件字节数做前置校验；不是整条消息的总附件容量，也不是图片上下文 token 上限。

发布基线的路由在 Content-Length 与实收长度不符时返回 400 `Upload is incomplete or its checksum does not match. Please retry.`。旧工作区 `55eb6a02` 缺少该长度校验，存在部分内容继续进入存储的代码风险；未证明线上发生过损坏落库。无 Content-Length 的情况仍需独立核查。完整原始证据见 [10MiB 截断核查](web-upload-10mib-truncation-2026-11-05.md)。线上实际配置、日志和完整上传边界尚未完成端到端验证。

## 3 Codex 图片处理调研

详见 [Agent 图片预处理一手资料核查](agent-image-preprocessing-primary-sources-2026-11-05.md)。官方公开 Codex 源码固定到 `388aee4b26226778701a7fa749354c44f74b4394`：

- 按 detail 模式和模型能力进行缩放。high 策略最大边 2048 px、最多 2500 个 32px patch；original 策略最大边 6000 px、最多 10000 patch。
- PNG、JPEG、WebP 若不需要缩放，可保留原始字节。不是所有图片都转成有损 JPEG。
- TUI 有累计图片表示的字节预算，并在准备失败或取消时恢复草稿。
- 已核查的图片准备通路没有默认 OCR 或语义摘要步骤。公开 CLI/core 的源码不能代替闭源桌面 UI 内部实现的实测。

因此，本轮学习其紧凑的图片上下文展示、清楚的数量与恢复操作，不照搬数值，也不偷改 Aihub 模型的图像输入。Masterino 当前每图固定估 1000 tokens、原图转 base64、下一条用户消息后不再携带旧图，均保持现状；准确估算和图片压缩另立范围。

十张是条目数量防护，10MiB 是上传请求体边界，两者都不能替代模型上下文预算；多张限额内的大图仍可能带来较大的请求和视觉 token 开销。缩略图仅用于展示，本轮不会据此声称已压缩模型输入或降低 token 消耗。后续图片预处理应按实际模型能力独立设计，并验证截图小字可读性、图片顺序、原图可追溯和预算估算，避免仅按文件字节数压缩。

## 4 十张图片规则

产品上限为每条消息最多十张图片，不是每次打开文件选择器十张，也不是全部附件最多十个。若实际模型另有限制，应取更严格的有效限制；本轮不伪造模型能力。

1. 所有入口共用同一客户端校验：回形针、首页加号、文件选择、多次追加、拖拽、粘贴、历史图片“加入输入”、编辑重发及重新生成中可调整的附件。
2. 已接收和正在接收的图片都占名额；在异步解码或 IPC 之前预留名额，防止两批同时进入绕过十张。取消、失败、移除释放对应名额；回调不能把已经取消的图片加回来。
3. 批量超过剩余名额，按确定的选择顺序加入可容纳部分，剩余部分明确列为“未添加”，一次提示“已添加 2 张，另 3 张超出上限”。不能静默丢弃，也不能上传后才拒绝。
4. 十张图片仍可追加普通文件。重复选择仍按实际进入消息的图片条目计数；本轮不按文件名或内容自动去重，避免改变既有输入语义，可在管理视图提示重复。
5. 提交前再次校验，优先于清空输入框、创建新话题或保存消息。原有请求组装防御检查保留。旧数据超过十张时，编辑或重发前解释如何减少图片，不通过后台静默截断。
6. 显示“图片 N/10”，仅在有图片时出现；达到上限仍允许用户打开管理视图和添加文件，新的图片入口给出原因而非失去响应。键盘和屏幕阅读器可获知剩余名额。
7. 图片类型、数量、平台大小限制在进入上传或解码前统一校验。因大小被拒绝的图片不占有效名额；拒绝原因保留在“未添加”列表中，重试仍重新校验。已进入草稿的历史失败项保留终态卡片，用户明确处理或移除后再发送。

## 5 图片和文件的统一展示

### 输入区

- 图片显示约 72–88px 的缩略图，保留完整比例或明确裁切的视觉边界，配当前顺序和可访问名称。长文件名在 hover、focus 或详情中查看，不让名称挤掉图片。
- 最多展示两行，超过部分显示“查看全部 N 张”，打开可管理的网格；窄屏改水平缩略图带。输入框不随几十个卡片无限增高。
- 普通文件用紧凑文件卡：格式图标、文件名、大小、一行状态。图片和文档可以混合，但类型易区分。
- 移除、重试与预览是独立操作区域，移除不能触发预览。预览关闭恢复到原缩略图焦点。
- 状态统一为本地准备中、上传中、解析中、可发送、已失败。失败保留原因和恢复动作；文字草稿保留。批量失败用一条聚合反馈，不连续弹十个 toast。

### 消息区

- 同条消息的图片以 1 张适配、2–4 张网格、5–10 张紧凑网格和折叠展示；旧十四图数据也能浏览，不能崩溃或全部变成大文档卡。
- 同一消息使用一个预览组，支持上一张、下一张、键盘方向键、缩放、Esc 一次关闭、当前位置“2/6”。首尾不循环，按钮到边界时正确禁用。
- 本地图片可懒加载缩略图。只读检查状态不应把所有历史原图转成 base64；使用已有的本地预览权限路径，不扩大目录授权。
- 设备不可用、原文件移动或版本变化时显示占位和“请在原设备重新选择”，不能无限 loading。图片卡的“加入本轮”作为次级操作，不能自动把所有历史图重新加入上下文。
- 云端与本地图片采用相同尺寸和预览交互，只在详情呈现不同来源。不得把“本机附件”解释成模型输入永不出设备。

实现建议复用一套 `AttachmentStrip`、`MessageImageGrid` 和单一 `ImagePreview` 职责，名称可随代码评审调整。图片缩略图内部关闭独立预览事件，外层只使用一个预览器。优先使用 `@lobehub/ui/base-ui` 的 Modal/Popover 等 primitive，样式使用 `createStaticStyles` 与 `cssVar`。新增英文与简体中文文案按项目规则同步。

## 6 Web 能力受限提示与客户端下载

### 识别条件

入口判断使用产品平台能力 `!isDesktop`，不要通过 User-Agent 中是否含“Mac”判断。企业微信 H5、内嵌网页与小程序的 web-view 按 Web 规则；真正原生小程序上传 API 需单独验收，不能仅凭外观认定。

| 原因 | Web 主提示与恢复 | 是否推荐客户端 |
| --- | --- | --- |
| 当前普通 Web 上传链路，选择文件大于 10,485,760 字节 | 上传前提示“当前网页版单个附件上限为 10 MiB。请选择更小的文件，或使用客户端在本机分析。”显示实际大小与上限 | 是；不发送该文件的上传或解析请求 |
| 上传阶段 HTTP 413 | “当前网页版无法上传此大小的附件。可换用较小文件，或使用客户端在本机分析。”仅在对应链路限额明确时显示数值 | 是 |
| 上传阶段 400 完整性失败，且已知该请求体超过当前链路上限 | 显示大小受限，说明该附件未上传完整，提供换文件与客户端动作；不要让用户原样重试超限文件 | 是；不能仅凭状态码归因 |
| 上传阶段 400 完整性失败，但请求未超限或限额未知 | “附件未完整上传，请重试或重新选择文件。”保留诊断详情 | 否；不误导为大小超限 |
| 服务端明确不支持 `.xlsm` 等格式，或可靠的当前解析能力清单在选择前已确认 | “网页版暂不支持解析 .xlsm。可另存为 .xlsx 后重试，或使用客户端尝试本地分析。” | 是 |
| 上传成功但解析格式不支持 | “文件已上传，但网页版无法解析此格式”，同时提供移除与客户端引导 | 是，不得改成上传失败 |
| 同样适用于 App 的图片大小、模型不支持图片、超过十图 | 解释对应限制，提供减少、换图或切换模型操作 | 否 |
| 401、403、断网、超时、5xx、缺上传确认头、存储对象丢失 | 对应登录、权限、重试或联系支持；保留诊断详情 | 否 |
| 损坏文件、加密文件、未知解析失败 | 解释无法解析，提供另存、解除密码或重试 | 不把未知错误统一归为 Web 能力不足 |

### 大小校验与错误分类规则

1. 对本方案已核对的普通 Web 同源上传链路，使用集中维护的客户端能力规则：`file.size > 10 * 1024 * 1024` 时拒绝上传，等于上限允许进入原有流程。不要把 10,000,000 字节误当作本阈值；其他类型、尺寸或解析限制仍可能更严格，不能承诺小于上限一定能分析。
2. 能力规则绑定平台、上传链路和发布版本，不在每个组件重复写常量；本轮不新增服务端配置接口。上线前核对目标部署仍使用这一默认限制。若某部署的真实上限不同，同步客户端规则与文案；没有可信限额的其他链路不套用该数字，保留 413、完整性失败的独立兜底。管理员占位值 0 不作为能力源。
3. 首页加号、回形针、拖拽、粘贴、历史加入输入及编辑重发均复用校验；已有待上传项在重试和发送前再次检查。批量选择保留有效项，未接收项显示文件名、大小和原因，不占图片有效名额，不上传后才拒绝。
4. 普通上传一次 PUT 一个原始文件，各文件分别校验。例如两个各 6MiB 的文件不能因为合计 12MiB 被拒绝。技能包、知识库、生成媒体等独立上传器继续执行各自规则；不得借此扩大成全局 10MiB 限制。
5. 错误分类优先使用上传阶段、HTTP 状态、明确响应原因、该次请求的原始字节数与对应限额。400 必须同时具备完整性失败与超限依据才映射为大小受限；小文件 400、未知 400、校验失败、网络中断不能全归为平台限制。详细日志放在可展开详情，不把英文内部报错作为主文案。
6. 上传进度达到 100% 只代表传输进度，不代表存储和解析完成；保留现有上传确认及解析成功判定。截断或完整性失败项不得展示为就绪或参与发送。浏览器不允许页面强设 Content-Length，不应为 UI 分类修改请求头或协议。

App 本机附件不使用上述 Web PUT 限额；本地图片另有单图 10MiB 与像素限制，错误应说明本地原因。App 云端目标按真实上传链路处理限制，但不出现“下载客户端”的推广。客户端本地文件处理不代表发送给模型时内容永不出设备。

### 提示布局

已拒绝项的“未添加”列表或附件失败卡先展示原因与“换用文件”“使用客户端”动作。首次在同一草稿中遇到确认的 Web 能力限制，自动打开一次轻量、可关闭的说明弹层；同批多文件聚合为一个弹层，后续拒绝或失败保留内联入口，不重复打断输入。不支持格式和大小超限分别写明原因，不能统一成“分析失败”。

弹层标题为“使用客户端分析本地文件”，正文说明这次 Web 受限原因。主要按钮“下载客户端”，次要按钮“继续使用网页版”；关闭、Esc 与点击次要按钮都保留文字和附件状态，不自动提交、上传或切换话题。只有点击下载按钮后调用现有下载流程。

出现终态失败时，发送区显示“有 1 个附件未就绪，请移除或处理后发送”，不能继续说“文件仍在上传或分析中”。本轮不改变既有“错误附件阻塞发送”规则；如需仅发送文字，用户先明确移除失败附件，不能静默漏发。

选择阶段拒绝的文件尚未进入有效草稿：在“未添加”列表明确列出，用户通过“移除未添加项并继续”确认后可发送其余内容。不能静默跳过它们，也不为它们创建服务端文件记录。下载或关闭说明弹层本身不等于确认漏发附件。

### 复用现有 CDN 链路

- [现有下载 hook](https://github.com/chaaak6/Masterino/blob/d1226ecf/src/features/DesktopDownload/index.tsx#L13) 已使用 `/api/desktop/download`；其服务端会验证现有签名 manifest 并返回受信任 CDN artifact。复用这些能力，不新增硬编码安装包地址，不绕过签名验证或产品 `desktopApp` 功能开关。
- Mac 架构无法确定时让用户选择 Apple Silicon 或 Intel；Windows 使用现有目标；不支持的桌面系统解释可用平台，不下载错误安装包。
- 手机及企业微信内嵌浏览器显示“请在电脑上使用客户端”，提供用户点击的复制公开下载入口或查看桌面下载选项。不得在手机上自动下载 exe/dmg；不依赖弹出新窗口成功，复制失败要能看到并手动复制。链接不得带登录令牌、文件内容或私有附件地址。
- CDN 超时、503、manifest 无效、缺目标架构提供重试，不能误报已安装或分析已恢复。下载不会自动把 Web 已上传附件搬到客户端，应明确需要在客户端重新选择本机原文件。
- `.xlsm` 的客户端推荐是可恢复路径，不保证当前全部本地内置工具都支持它，不执行宏；另存为 `.xlsx` 应是真实格式转换，不能要求只改后缀。

## 7 实施拆分与风险控制

| 顺序 | 内容 | 主要涉及代码 |
| --- | --- | --- |
| 1 | 十张统一校验、Web 10MiB 前置校验、异步名额、拒绝清单与草稿保留 | `src/store/file/slices/chat/action.ts`，各上传入口，重试与发送前客户端校验 |
| 2 | 输入缩略图、文档卡、消息网格、单层预览 | `ChatInput/Desktop/ContextContainer`、`FilePreview`、移动输入；`Conversation/Messages/User` 下本地与云端附件展示 |
| 3 | 413、截断相关 400 与非超限错误分类；聚合受限提示；复用下载 UI | 上传诊断映射、客户端上传能力规则、`DesktopDownload`、相关 i18n；不改上传代理、Next 配置或解析器 |
| 4 | 完整矩阵验收与受影响功能回归 | [测试用例文档](attachment-ui-qa-cases-2026-11-05.md) |

存储引用、文件 ID、消息绑定与模型输入数组保持既有契约，UI 分组不能重排模型收到的图片。图片数限制按同一草稿隔离，切换助理、话题、项目、窗口时不能串扰。预览释放临时 object URL 的时机不能早于使用者关闭，也不能撤销用户原始文件。组件复用须保留本地权限边界、共享消息不可访问本机文件的占位和 Web 的同源上传路径。

## 8 验收标准

P0 图片数量、Web 大小前置校验、错误分类、平台隔离、文件安全、发送草稿和下载正确性全部通过；P1 核心 UI 与错误恢复全部通过。十图上限在并发入口也不可绕过；当前链路 10MiB+1 在上传前被拒绝，等于上限不因大小被拒绝；413、超限完整性 400 与普通 400 分别处理；有效文件不受同批总大小误拦截。Web 下载提示不出现在 App；有效请求的原图内容、顺序、source 与既有解析行为不变。

UI 前置校验与底层上传完整性分别记录验收结果：在隔离环境直接验证上传链路时，若截断文件被当作完整上传成功，列为发布阻断风险，另行处理，不能宣称 UI 已修复该服务端风险。本轮不通过改服务来让用例通过。线上边界与企微真机未验证时保留阻塞状态，本地函数复现不能替代生产端到端通过。

本方案作为实现与验收范围；实际测试结果见 [附件体验验收记录](../testing/attachment-experience-acceptance-2026-11-05.md)。服务端容量、Next Proxy 配置与解析器保持原有策略。
