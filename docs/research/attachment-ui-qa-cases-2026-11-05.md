# Masterino 图片与附件 UI 测试用例

本用例验证 [图片与附件 UI 改进方案](attachment-ui-improvement-plan-2026-11-05.md)，覆盖十张图片上限、图片与文件展示、Web 单文件 10MiB 前置校验、413 与截断相关 400 的错误恢复、客户端下载及周边回归。十张限制为每条消息的图片条目数；10MiB 为当前普通 Web 原始文件 PUT 链路的请求体边界，两者独立。App 本地附件、解析能力及模型图片上下文行为维持既有规则。用例的“预期”描述优化后的验收标准，不表示当前版本已通过。

## 1 执行记录与环境

每次执行记录产品版本、提交、Web 构建标识、服务端环境、浏览器或 App 版本、操作系统、账号角色、执行目标、模型及其图片能力、入口、结果与证据。涉及大小边界时另记 Next 版本、Proxy matcher、有效 `proxyClientMaxBodySize`、Ingress 限额和客户端能力规则版本；配置未知记未知，不把仓库清单当作线上实际值。结果仅用通过、失败、阻塞、未执行；阻塞写清原因，不计为通过。

| 环境代号 | 要求 |
| --- | --- |
| A | macOS App，执行目标本机；至少一轮 Windows App 对照 |
| W | Chrome Web，服务端上传；至少一轮 Safari 或 Edge 对照 |
| M | 手机浏览器，iOS 与 Android 各一轮 |
| Q | 企业微信真机内嵌 H5 或小程序 web-view，记录具体容器；不得用普通 Chrome 改 UA 代替真机 |
| S | 隔离测试环境，用于 400 完整性失败、413、401、403、5xx、CDN 不可用，以及绕过 UI 的底层上传验证；不改生产服务做故障注入 |

主路径在首页、助理新话题、已有普通话题、项目话题各执行一轮。App 的本机与云端目标分别记录，但只有真正 Web 容器可以触发“网页版受限”的客户端下载引导。App 即使使用云端执行目标，也不能误显示网页版提示。

大小测试分两条路径：**产品 UI 路径**验证超限在上传前被拒绝，不能为了抓到 400 或 413 而要求 UI 仍上传；**底层链路路径**仅在 S 中用测试工具直接请求普通上传入口，验证框架截断与完整性，不把它算作 UI 通过。浏览器页面不能手工设置 Content-Length，无该头的用例由测试客户端执行。本轮只编写用例，不启动故障注入或修改服务。

## 2 测试数据

所有数据使用合成素材，不上传真实生产、财务、人事或账号文件。不含 VBA 的 xlsm 可用于解析能力测试，但不覆盖有宏工作簿的全部内容特征。

| 素材 | 要求与用途 |
| --- | --- |
| P01–P12 | 十二张不同颜色或带可辨认数字的 PNG，320×200，内容互不相同，按文件名排序；检查顺序与十一张以上限制 |
| SAME | 同一图片同一路径重复选择；另有同名但内容不同文件；不以同名判断为同一内容 |
| IMG | PNG、JPEG、WebP、GIF、带透明通道 PNG；横图、竖图、超长截图、中文小字截图、照片、EXIF 旋转 JPEG |
| IMG_BAD | 损坏图片、零字节图、MIME 为空、扩展名大写、后缀与内容不符；不得为绕过模型能力而接受不安全输入 |
| IMG_SIZE | 在既有图片大小上限及解码尺寸上限的下方、等于、上方；单图 10MiB 与 10MiB 加一字节必须分别记录字节值 |
| DOC | 小 TXT、有效 PDF、DOCX、XLSX、CSV，文件名含中文、空格、超长名称；两份不同目录下的同名文件 |
| XLSM | 无 VBA 的有效宏启用 OpenXML 容器；另备真实合成含宏工作簿，仅在隔离环境测试且禁止执行宏；另存产生的有效 XLSX 作对照，不能直接改后缀 |
| SIZE | 10,000,000、10,485,759、10,485,760、10,485,761、11,534,336 字节的有效 TXT 与有效二进制文件；若目标部署有效上限为其他 L，另备 L−1、L、L＋1。同类文件通过格式校验，不能用损坏格式凑字节数 |
| SIZE_BATCH | 两个各 6MiB 的有效文件，以及小文件与 10MiB+1 文件混合批次；验证按文件判定，不按总量拒绝 |
| BODY | S 中使用同一内容的 64KiB 与70,000字节分块输入；有 Content-Length 与无该头的传输分别准备；不在浏览器页面伪造禁止设置的请求头 |
| FAIL | 损坏或加密 PDF、网络超时、无权限文件、对象缺失等，区分未知解析失败与平台能力受限 |
| HIST | 有旧图片、本地失效图片、云端图片及历史超过十图的旧消息；保留合法测试会话，不伪造生产数据库 |

每个文件记录文件名、MIME、实际字节数、图像宽高、SHA-256。不能用压缩后文件大小代替原始大小，也不能从某类图片的阈值推断普通文件的 Web 上限。

10MiB 精确等于 10,485,760 字节，10,000,000 字节小于该限额。当前普通 Web PUT 一个请求对应一个原始文件；本轮不增加整条消息 10MiB 总量规则。App 本地单图 10MiB、像素/边长、模型能力及类型校验分别记录，不与 Web 上传截断混判。

## 8 证据和发布门槛

UI类P0记录可辨认界面与请求/本地状态证据；底层链路类P0记录请求与服务端/存储证据，不伪造UI截图。证据需脱敏。大小边界记录文件原始字节、请求体实际字节、Content-Length是否存在、路由实收字节、HTTP状态、阶段、框架警告及存储对象大小/SHA-256；不存在对象也要记录。无法取得的字段明确记未知或阻塞。前置拒绝用例记录无该文件PUT/解析请求，不能强求出现HTTP错误。多图记录原文件与最终顺序；下载记录版本、平台、架构与允许CDN主机。不可只凭toast消失、空白回复、文件名出现或上传进度100%判为成功。

用例定义不等于执行通过，实际执行状态见 [附件体验验收记录](../testing/attachment-experience-acceptance-2026-11-05.md)。第1节分别列历史Computer Use与框架函数复现，不能升级为线上端到端通过。P0全部通过，P1核心展示与恢复通过，才可宣称本轮目标完成。若底层截断被当作完整成功，单列既有上传完整性风险并阻断发布，另行处理，不将其算为UI已修复；本轮不改服务。Q真机、真实大小边界或CDN异常若阻塞，保留负责人和补测条件，不用模拟结果替代。生产环境只做低负载合成素材验证；直接绕过UI、故障注入及压力测试限S环境。

建议自动化优先覆盖：十图并发名额与释放、精确字节边界与批次独立校验、所有添加入口、413/超限完整性400/非超限400分类、平台门控、单层预览、草稿保留及下载目标映射。人工重点覆盖：多图识别效率、布局和焦点、企微容器、长截图可读性、实际CDN下载与真实部署限额。文档改动无需运行全仓测试；后续实现按改动模块跑定向Vitest与类型检查，再执行本矩阵。
