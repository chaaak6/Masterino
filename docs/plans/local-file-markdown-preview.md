# 工作区 Markdown 预览改进方案

从 `origin/main` 的 `7af1f2c8`（v1.3.16）出发，改进 Agent 会话「文件 → 预览」中的 README 阅读体验。首版验收以截图里的操作为准：SVG 横幅正常显示，提示块有明确样式，GIF 可见且能打开对应的工作区视频，文档目录和相对链接可用。浏览器组件实测和源码依据见[前置调研](../research/local-file-markdown-preview-2026-11-27.md)。

## 单次交付范围

| 功能组             | 交付                                                | 完成条件                                                                  |
| ------------------ | --------------------------------------------------- | ------------------------------------------------------------------------- |
| 渲染和图片         | 五种 GitHub 提示块，HTML 图片、链接图片及缺图反馈   | 预览能读出截图里的横幅和 GIF。标准 Markdown 写法也通过同一套验收。        |
| 导航和跨设备       | 同页标题、跨文件链接及片段，CLI 的 `.markdown` 识别 | 文档目录可用，相对链接打开当前设备的工作区标签，已有标签复用。            |
| 视频与常见补充标签 | 本机 MP4 打开动作，远端视频状态，`details/summary`  | 一个 README 样例从打开到点击 GIF 的整条路径可以验收，远端能力有明确反馈。 |

常用正文回归覆盖表格、任务列表、删除线、代码高亮、脚注、公式、Mermaid 和 front matter。预览和原文共用当前编辑缓冲，用户可以在原文查看完整标签与属性。

## 1. 扩展文件预览渲染

- 从 `TextPreviewPane` 提取文件专用的 Markdown 正文组件，接收正文、文件路径、工作区根目录、设备和当前预览容器。正文组件负责插件和元素映射，现有面板负责文件读取、视图切换与保存。改动落在 [LocalFile Body](../../src/features/Portal/LocalFile/Body.tsx#L148) 和同目录组件。
- 优先用现成的 `enableGithubAlert` 支持 NOTE、TIP、IMPORTANT、WARNING 和 CAUTION。对标记后直接接正文的常见写法，在 Markdown AST 中将引用首段的开头归一化为标准结构，保留强调、链接和后续段落。普通引用以及围栏和行内代码里的标记继续按其原有 Markdown 语法渲染。
- 对内嵌 HTML，在文件专用的 `rehypePluginsAhead` 中先解析，再按明确的标签、属性和协议规则清理，随后进入依赖自带的提示块与公式插件。优先验证当前锁定渲染器能否按这个顺序接入。若需要引用解析、清理或标题 slug 工具，声明为直接依赖并锁定。支持的标签包括 `img` 和 `a`，同时支持 `details`、`summary`。图片保留 `src`、`alt`、`title` 及受限宽高，链接保留 `href`、`title`。新增的 HTML 链接接受工作区相对路径、文档片段和 HTTP(S)。图片接受工作区相对路径和 HTTP(S)。交互由预览组件提供，清理时去掉文档指定的事件、样式和嵌入容器，其原始写法可在「原文」查看。
- 清理规则需要同时保留标准 Markdown 生成的语义和必要属性，特别是任务列表的只读复选框、表格对齐、代码语言类以及脚注互相引用。生成的 ID 采用受控前缀，同步处理对应片段。验收时比较清理前后的等价文档结构，并测试代码示例中的 HTML 仍是代码文本。
- 把 HTML 图片和 Markdown 图片交给同一个 [MarkdownImage](../../src/features/Portal/LocalFile/MarkdownImage.tsx)。沿用 `ProjectFileService`、`accept: 'image'` 和设备维度的缓存键。宽高接受有效像素或百分比，展示宽度受面板约束，保持图片比例。链接内使用可内联的图片展示，点击和键盘激活交给外层链接。独立图片提供原有放大交互。
- 区分加载、成功和失败。加载时保留适当占位。读取失败或图片解码失败时显示 alt，缺少 alt 时显示文件名，配一条简短的失败状态。切文件时清理 Blob URL，与当前正文、设备和资源路径匹配后再显示图片。新文案落在 [chat 命名空间](../../packages/locales/src/default/chat.ts)，同步 en-US 与 zh-CN。

## 2. 相对链接与标题导航

| 链接写法                     | 预览内行为                                                         |
| ---------------------------- | ------------------------------------------------------------------ |
| `#安装`                      | 找到当前预览的标题，在面板内滚动并聚焦。                           |
| `docs/setup.md`              | 根据当前 Markdown 所在目录解析，打开或激活同设备的目标文件标签。   |
| `../guide.md#安装`           | 允许仍位于当前工作区的上级相对路径。目标正文就绪后，定位对应标题。 |
| 有效 HTTP(S) 链接            | 使用既有外链行为。                                                 |
| 无效链接、越界路径、缺失标题 | 预览保持可读，反馈无法打开文件或找不到章节。                       |
| Markdown 脚注                | 在当前预览内往返正文与脚注。                                       |

- 为标题生成与 GitHub 常见写法一致的 slug，覆盖中文、符号及同名标题后缀。内部用当前容器限定查找范围，区分标题和脚注，防止多个实例的相同 slug 互相干扰。支持多次点击同一链接和键盘操作。
- 对相对资源统一执行路径分类、一次解码和路径归一化。文件部分与 fragment 分开保留，按源文件目录解析，覆盖空格、中文、点段、Windows 盘符及 UNC 工作区。绝对路径、设备路径和不受支持的协议走不可用状态。相对链接和图片只使用当前设备与工作区上下文，并执行真实路径授权检查。尤其验证符号链接、已经单独授权的外部文件，以及从外部附件打开的 Markdown，确保派生资源访问仍限定在当前工作区。
- 文件导航复用 [Portal 的 `openLocalFile`](../../src/store/chat/slices/portal/action.ts#L470)。跨文件 fragment 作为待处理的导航请求，以目标标签标识和请求标识关联，在文档就绪后消费。编辑缓冲继续按现有标签 ID 读写，由设备、目录、文件路径确定。点击带片段的目标链接时进入目标的「预览」，保留未保存的编辑内容。重复打开同一文件复用标签，切换工作区或设备时不会消费其他标签的导航请求。
- 在 [远端 CLI 扩展名映射](../../packages/device-control/src/filePreview.ts#L19) 补 `.markdown`，在现有设备预览用例里与 `.md`、`.mdx` 一起验证。Markdown 跨端验收同时覆盖本机 Electron、Web 访问已绑定设备和远端 CLI。

## 3. 视频与补充标签

GIF 外层链接进入同一个工作区文件标签流程。视频标签显示文件名、可用动作和失败状态。本机 Electron 提供「用系统播放器打开」，主进程在同一次调用中核对工作区、真实路径、普通文件及媒体类型，再交给系统。当前通用 `handleOpenLocalFile` 缺少工作区范围参数，因此由媒体入口采用带工作区校验的打开动作。远端首版在标签内明确显示当前设备视频预览不可用。对远端 MP4 播放另立后续阶段，验收条件包括支持范围读取、设备断线与大文件内存开销。[现有系统打开](../../apps/desktop/src/main/controllers/LocalFileCtr.ts#L398) · [预览协议](../../apps/desktop/src/main/core/infrastructure/LocalFileProtocolManager.ts#L133) · [远端预览类型](../../packages/device-control/src/filePreview.ts#L61)

`details/summary` 使用浏览器原生折叠语义，支持键盘，尊重文档给定的初始展开状态。用包含正文和代码的样例验证常见 README 写法。
