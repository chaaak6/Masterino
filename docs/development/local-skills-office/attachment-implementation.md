# Attachment implementation

Messages carry a nullable `{schemaVersion: 1, items}` JSONB envelope. Local entries use `attachmentId` for the message and `localResourceId` for the device map; uploaded entries carry a real `fileId`. Paths and Base64 are absent from the envelope. Shared normalization merges legacy file/image lists without duplicate uploaded IDs. Create, paired create, batch import, update, addFiles, and file deletion keep uploaded JSON and `messages_files` in one transaction; uploaded ownership is checked before writes.

Desktop paperclip, paste and main conversation drag pass the topic to the same intake action. The current topic/draft execution intent chooses local intake. Preload captures the native File path before conversion; main only accepts an original reference when supplied File bytes match its contents. Pathless files go into managed draft storage. The device map validates realpath, device, size and content hash. Tool preparation copies to the topic scratch `.attachments/<localResourceId>/` directory and registers a topic binding. `validatePreparedLocalAttachment` supports main-process exact-file read grants. Original directories receive no grant from this flow.

At request assembly local documents produce an ID/name/type/size/version/path manifest, without automatic full parsing. Images are read as image data URLs at request time. Only latest-user selected images remain enabled by default; history images become explicit ID placeholders. A non-vision model rejects selected images. Limits are 10 images, 10 MiB each, 8192 pixels per dimension, and 40 megapixels at intake. Native image encoding is cached by resource/version after verifying the source. OpenAI-compatible and Anthropic-compatible SDK fetch boundaries enforce a 20 MiB serialized request ceiling, including retries; this is independent of preprocessing and does not claim to reduce network payload through caching. Video fallback stays enabled independently.

Cloud bootstrap now uses ID directories and version-specific per-file markers. Downloaded bytes are size-checked and renamed before registration. New attachments are reconsidered on later calls; failed preparation is visible and retried.

Verification: shared envelope tests; real temporary-file/Blob identity, device and version tests; historical/current image context tests; image-hook video regression; true serialized fetch byte guard; DB create/update/file deletion suites; cloud bootstrap/retry tests. Full GUI, provider/proxy and packaged-app acceptance belongs to the separate acceptance report. The model request ceiling currently covers OpenAI and Anthropic compatible factories; other provider families require explicit adapters before claiming equivalent support.
