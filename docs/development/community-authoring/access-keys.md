# 后台访问 Key

管理后台 `/access-keys` 提供创建、搜索、查看/复制、停用/启用和删除。创建时填写名称、用途、可选有效期；留空表示长期有效。删除需要再次确认。

Key 使用已有的 `sk-lh-` 认证机制，绑定创建管理员，沿用该账号的权限。没有新增业务 scopes，可用于 CLI MCP / Skill 投稿以及后续支持同一认证机制的接口。平台权限仍由既有接口检查，不因持有 Key 而绕过审批发布。

所有具有后台访问权限的管理员能集中管理后台创建的 Key。数据库仅加上用途和管理标志，凭证继续使用已有加密/哈希逻辑；列表只返回元数据，查看时单独取凭证，创建、查看、启停和删除记录操作审计，审计不保存凭证。

个人及工作区 Key 不进入此目录；个人设置的列表、修改、删除及“删除全部”也不触及后台 Key。认证与最近使用时间更新继续支持两类 Key。

测试与生产使用各自的数据库、加密配置和 Key。生产部署迁移后，由管理员登录生产后台创建，CLI 设置相应的服务地址和 Key，无需通过 Aliyun CLI 签发。第三方 MCP 的 API Key 是另一种凭证，配置在 MCP 资源的服务端连接中，不与 Masterino 访问 Key 混用。

## BDD 与测试环境验收

`e2e/managed-api-keys.config.cjs`：使用两名管理员和一名普通员工，验证创建和有效期、元数据不含凭证、跨管理员查看、归属账号认证、停用/恢复/删除、个人 Key 隔离、普通员工拒绝访问及过去有效期拒绝。

在 `e2e/` 运行 `pnpm exec cucumber-js --config managed-api-keys.config.cjs`。仓库外 `COMMUNITY_CLI_CREDENTIALS` 指向 CLI 环境配置文件，`ADMIN_ACCEPTANCE_CREDENTIALS` 指向包含测试管理员和员工邮箱、临时测试密码的 JSON。先通过测试环境维护流程赋予测试管理员身份，完成后撤销；脚本仅删除当次创建的测试 Key，不操作现有 Key。
