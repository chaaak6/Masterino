# 客户端更新、登录存储与退出清理验收

状态：开发前测试基线；执行结果在文末逐项记录。适用于 Windows x64、macOS arm64/x64。

## 环境与准备

- 服务端仅使用 `https://mlai-test.bielcrystal.com` 和 `masterino-test` 集群命名空间。不得修改生产 Deployment、OSS 正式更新清单或正式客户端资料目录。
- 使用带独立身份及用户目录的测试 App。记录 App 版本、架构、主进程 PID、`userData`、服务器地址、安装路径；正式目录禁止作为安装故障用例的目标。
- 安装升级测试使用两份可区分版本的测试 App（A → B）；B 必须真正启动并返回自己的版本，不能只用模拟完成消息替代安装。
- 更新清单与安装包使用隔离的测试源和测试签名密钥。日志至少能区分清单请求、HEAD、安装包 GET、Range 和实际字节数；禁止记录 Token。
- 先备份测试资料目录。准备：有效安装包、同名损坏文件、可控慢速/中断下载、充足/不足磁盘空间、可写/不可写安装目录。
- 开发者工具观察 Console、Network；下载发生在主进程时，以主进程下载日志与测试源请求日志为准，不能仅凭 renderer Network 空白断定无下载。
- 测试凭据只用测试账号或合成令牌。`auth.json` 验证只输出字段是否存在、权限、更新时间，不在截图或报告输出值。

| U04 | 下载过程中取消，然后不再点击并重启 App | 请求停止、系统进度清除，不在后台恢复；用户可再次点击重试。 |

| I02 | 同时启动长 Shell、Python 文档处理、可用的 Agent/MCP 子进程，再点“退出并安装” | 停止接收新任务；显示结束任务阶段；等待所有受管进程树退出后才替换。记录安装前后 PID、子孙 PID 和监听端口。 |
| I03 | 使用忽略正常终止信号的合成任务重复 I02 | 超时升级终止并等待退出；无遗留子进程。不能把“已发信号”当作“已退出”。 |
| I04 | 清理期间重复点击、窗口关闭、菜单退出 | 清理只执行一次，不重复启动安装器、不提前释放退出屏障。 |
| I05 | 安装目录不可写/空间不足/包错误 | 在主 App 退出前尽可能完成预检并给出原因；失败不会破坏原 App；允许取消或重试。 |
| I06 | macOS A → B：观察准备、挂载/展开、复制、替换、启动 | 复制进度真实；未知时长阶段用状态文字；原 App 退出后仍有进度窗；B 版本可核对。替换失败恢复 A。 |
| I07 | Windows A → B：观察 NSIS 安装窗口 | 安装器可见，不静默；正常显示解压/复制进度，完成后启动 B；不同时启动两个安装器。 |
| I08 | B 启动失败/辅助程序异常 | 有清晰失败记录和恢复入口；macOS 旧版备份可恢复；辅助程序完成或失败后结束，无永久孤儿进程。 |
| A01 | 新资料目录企微登录、使用聊天、退出重启 | Windows/macOS 固定 userData 下生成明文 `auth.json`；无 safeStorage Token 写入；重启恢复登录。 |

## 自动检查范围

仅为高价值行为补充测试：缓存命中不发 GET、错误缓存拒绝；Token 原子持久化/迁移/服务器隔离；退出等待与终止升级；辅助安装事务。复用现有更新器/凭据测试，避免新增大量展示层快照。

### 2026-10-27 实际执行（PR #149）

平台：macOS 27 / Apple Silicon。使用独立测试 bundle `com.masterino.desktop.update-acceptance`、
独立 profile `masterino-desktop-local-272026aabbcc`，连接 `mlai-test.bielcrystal.com`；
A/B 是复制完整 Electron 运行时并替换本分支编译产物的 ad-hoc 测试包，不覆盖正式安装。
正式版本号未调整。测试发布版本 1.3.11 → 1.3.12；故障注入版本 1.3.13。
本地源签名、公钥注入、请求统计使用 `apps/desktop/scripts/update-test/signed-fixture.mjs`，
可操作步骤在同目录 README。测试私钥及认证 Token 不进入仓库或报告。

发现并修复：重试沿用上次进度；待装缓存过早按年龄删除；检查期间状态竞争；
安装前清理失败时必须等其他清理完毕再取消安装并恢复网关；安装器启动失败后恢复主流程；
下载/清单缺少超时；静态文件服务异步清理的旧测试未等待。

11:49 的崩溃日志对应 PID 88577、EXC_BREAKPOINT/SIGTRAP，现场 stdout 为
`Unable to find helper app`。原因是验收包改了 CFBundleName / 主二进制名却未同步 Electron Helper，
修正测试打包后消失；不是从 stripped 栈里的 `ares_dns_*` 名字推断 DNS 故障。
原生安装器另外增加主二进制、Framework 及 Electron Helper 路径校验，替换前拒绝不完整运行时。

安装实测还发现 Electron 在文件扫描退出收尾时可能卡于 Node `Environment::CleanupHandles`；
首次旧安装器正确中止且保留原 App。修复后，仅在受管任务已完成清理且显式确认安装后，
独立 helper 等待旧进程 30 秒，再核对 PID 对应同一 App 路径，TERM、等待、必要时强制终止该旧主进程，
确认消失后才替换；不会按进程名结束其他应用。随后真实安装成功。

### 平台与验收限制

- Windows x64 已通过 CI 构建与进程树测试；本机没有 Windows GUI 会话，**I07 的真实 NSIS 界面及 Windows 旧资料交互迁移仍需测试同学实机执行**。
- Intel Mac helper 交叉编译通过，本机只真实运行 arm64。
- I02 的每一种外部 Agent / MCP / Python 组合未逐一在 GUI 执行；相关等待/终止逻辑及实际 Shell 父子树已测，不将其写成所有工具集成均通过。
- R01 真实模型聊天通过；原生文件选择器在此 CUA 会话中出现 Open 不可用，未将附件全链路列为通过，也未修改附件业务逻辑。
- 全量 type-check 有原有初始化/unknown catch/历史测试类型问题；不宣称全量类型检查通过。以相关测试、构建、lint 和 CI 结果分别记录。
