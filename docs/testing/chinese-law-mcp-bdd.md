# 内网法条 MCP 测试与验收

状态：2026-11-04 已实现并在测试集群执行真实后台／Electron 验收。基线：main d1226ecf（1.3.12）。用例在实现前定义，执行结果见文末。

## 范围与边界

新增独立服务、固定公开语料、测试环境部署配置，复用现有共享 MCP 调用和审批发布链路。不修改客户端、模型路由、元典配置、数据库结构及生产部署。

自动化通过 HTTP MCP initialize、tools/list、tools/call 验证真实公开接口；真人验收通过测试管理后台和连接测试集群的 Electron，结合 Network、Console 与服务日志确认。只对协议、数据装载和检索写必要测试，不增加 UI 单测。

## 测试环境既有问题与验收实例

测试环境有历史预览 Ingress 重叠。旧 `masterino-admin-ingress` 的七条 MCP／创建／验证路径指向无 Endpoint 的 `masterino-community-api`，最初返回 nginx 502；健康的原 Market 则缺少 `POST /api/internal/resources`，创建返回 404。这两个问题均发生在新 MCP 外部。

为完成真实审批验收，新增 `masterino-law-acceptance-api`、`masterino-law-acceptance-market` 两个独立 Deployment／Service，复用测试环境原配置与同一测试数据库。API 复用原主服务镜像，仅覆盖 MARKET_BASE_URL；Market 使用本分支（未修改 Market 源码）远程构建的 `sha256:72a4a333e8543d3cb2a6b73552d9a7c0e0ac88891850439e3d847b83c9be6193`。没有迁移／修改数据库结构，也没有替换已有 Deployment。

仅将旧后台以下路径指向验收 API：`market.getMcpCategories`、`market.getMcpList`、`market.getMcpManifest`、`market.getMcpDetail`、`admin.createCatalogResource`、`admin.verifyCatalogMcp`（均 `/trpc/lambda/` 前缀），以及 `/trpc/tools/market.callCloudMcpEndpoint`。另新增 `masterino-law-acceptance-mcp` Ingress，在测试客户端域名只覆盖上述五条 MCP 路径，普通对话及其他功能路径不变。真实三项工具批量请求仍经过原通用路由，证明已有主服务链路可用。

这些操作只用于测试部署，不作为产品代码变更。原 Ingress 的私有备份在 `/tmp/masterino-law-test-admin-ingress-before.json`，后续回滚应只恢复上述七条路径（先核对当前值，避免覆盖其他人的测试改动）；删除新增验收 Ingress 和两个验收 Deployment／Service 即可移除临时实例。新法条服务及已发布测试资源单独保留供 review。正式上线前应按常规更新 Market 到包含创建接口的版本，不复制这些历史测试路由修复。
