## 环境与证据口径

- 正式测试站点为 https://mlai-test.bielcrystal.com/ ，Computer Use 已直接打开并确认 `masterinoTest` 正常登录。不要把 `127.0.0.1:9887/signin` 遗留页面当成测试站点地址。
- Electron 为本地源码 `pnpm dev:desktop:test`，专用 `masterino-desktop-test-server` profile，后端同上。没有操作另一个 PR153 QA 应用。
- Web 为本分支 Vite 前端与测试后端组合，本机入口 `http://localhost:9887/`。它用于运行尚未部署的代码；正式测试域名的已部署 SPA 不能证明本分支 UI 已生效。已通过页面脚本 URL 确认本地 `src/spa/entry.web.tsx`。
- 测试站点现有调试 HTML 的 CSP 不允许本机脚本，本轮没有关闭 CSP。临时转发器仅监听回环地址，经正常登录联调；没有导出或注入会话令牌。后期只把签名上传 URL 的测试源站替换为本机转发入口，以在本机注入响应；保留路径、签名参数和测试后端鉴权。
- A 为 macOS Electron；Web 实操使用 IAB Chromium。没有把 IAB 结果冒充 Chrome/Safari/Edge 全矩阵，也没有把桌面缩放冒充手机或企微真机。
- 500、完整性400、403、manifest503 仅为本机测试转发器模拟；其他成功上传、解析和模型回复来自测试集群。故障开关已删除，没有更改集群配置。素材均为合成文件，没有上传生产业务资料。

下表“通过”只覆盖备注中明确写出的环境、替代素材或自动化范围，不表示所有环境组合已通过。未执行、阻塞均不计通过。85条用例已逐项记账，不能宣称跨平台验收完成，也不建议据此跳过 QA 发布门槛。

## 图片复制与文件定位修复验收

用户反馈复制得到 base64、缺少所在文件夹入口后，在同一分支继续修复。原生图片菜单此前只有复制地址，data URL 因而成为字符串；通用浏览器复制工具也存在文本兜底。本次增加真正的图片复制：Electron 本机附件经主进程验证设备、引用身份、路径及内容版本后调用 `clipboard.writeImage`；其他原生图片菜单使用 `webContents.copyImageAt`；Web 使用 `ClipboardItem` 的 `image/png` 数据，失败明确提示，不再退化为文本。复制是系统剪贴板操作，不影响模型输入图。

本机图库缩略图和大图增加所在文件夹入口；只传附件引用，由主进程解析已授权路径，使用系统文件定位。原文件有路径时定位原文件，从剪贴板接收的受管理图片则定位受管理文件。Web 云端图片没有虚构的本机文件夹入口。图片动作日志只记录 action/attachmentId 或错误枚举，不记录像素、base64 或本机路径。

实际调试修复了 ContextMenuTrigger 自定义子组件吞掉 DOM 事件、两个 ContextMenuHost 导致重复宿主的问题。最终只挂载一个 base-ui ContextMenuHost，缩略图与大图都能打开统一菜单。
