## 用例校正

- 默认聊天输入区只显示供应商品牌图标；首页使用文字模型标签。检查名字更新时看实际具有文字标签的入口和模型面板，不能要求所有布局都出现文字。
- 关闭静默刷新时，控制器收到 `disabled` 后清除静默覆盖，并回到原有 provider runtime 读取；原有“打开面板时读取”仍可能显示新的发布名。开-01 应验收独立静默目录不再应用、旧路径和手动刷新继续可用，不能要求打开面板后名字绝不更新。服务端开关也不是推送给已打开客户端，必须等下次检查。
- 同一助理的模型选择由 `updateAgentConfigById` 保存，多个话题共享助理配置。归-05 应验收消息隔离与不被静默刷新自动换模型；不能凭空要求每个话题独立保存不同模型。
- 图片/视频图标是展示证据，不能通过临时发布图标来给模型授予实际看图能力；后台上下文、类别和参考价仍不覆盖运行时上下文、路由和 Aihub 计费。

## 缺陷、最小修复与验证

失败账号：管理员 `biel`，客户端 `10507479`；模型 `deepseek-v4-pro`。11:06:41回滚界面原文“已回滚，并生成新的发布版本”，列表仍有“有草稿修改”；维护页显示原名而不是QA145。11:07:14再次发布原文“模型说明已发布”，已发布名错误跳回原名。整个故障过程客户端主话题仍为 `tpc_ic4JTPKMZgHa`，选中 `newapi/deepseek-v4-pro` 没有被自动换掉。

根因是 repository 的回滚事务只更新 `published`，保留了回滚前的 `draft`，下一次发布又读取该旧草稿。修复在同一个既有事务里把 `draft` 同步为实际发布的 `description`；并发版本检查、历史、审计及generation保持原样。修改现有PostgreSQL集成用例断言整个草稿与发布内容相同，并在回滚后再次发布验证内容不反弹；没有新增UI测试文件。普通成员另在真实Electron DevTools发起只读目录请求，返回 `PR145_PERMISSION 403`，错误体为 `FORBIDDEN`，未暴露目录数据。

复现先红后绿：

```sh
CATALOG_BDD_DATABASE_URL=postgresql://postgres@127.0.0.1:15436/catalog_bdd \
  bunx vitest run --silent=passed-only apps/server/src/services/modelCatalog/repository.integration.test.ts
```

修复前1失败、2通过，失败差异为 `First` / `Second`；修复后3/3通过。另有目录投影、运行时guard、静默控制器、图标、详情、provider store六组45/45通过。改动文件ESLint、Prettier和 `git diff --check` 通过。

根项目 `bun run type-check` 在本机资源受限下首次中止，限制Go并发后的重跑结束，44个诊断均落在未修改的React/UI依赖类型相关文件，本次两个repository文件0诊断；这不等同于全项目类型检查通过。PR最新CI应作为最终全量依据。

真实修复重验没有构建镜像：以测试服务当前镜像启动临时 `masterino-pr145-acceptance`，启动前只把编译出的repository发布更新补上同一处 `draft` 赋值；专用Ingress仅将两个测试域名的 `modelCatalog.publish` / `modelCatalog.rollback` 精确路径接到此实例。该实例用于验证事务行为，不代表整条分支已部署。完成后删除专用Ingress、Service、Deployment，原服务仍健康、0重启。测试服务日志未见本轮catalog错误；客户端Console有既有React/antd开发警告，未将其作为本次回滚缺陷处理。
