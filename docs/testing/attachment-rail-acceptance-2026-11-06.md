# 消息附件横向展示验收记录

本次继续在 `codex/attachment-experience` 分支、PR #156 实现。图片与文件移至每条用户消息的文字气泡上方，右侧对齐；图片外框72×72px，文件卡184×72px，统一单行横向浏览。图片保留完整适配，文件显示名称、大小及本机可用状态；单一大图预览支持左右拖动切图，放大后拖动查看局部，底部提供可点击的图片操作菜单。文字气泡独立收缩；仅附件消息没有空文字气泡。

复用现有 `aboveMessage`、图库、文件预览与本机引用验证。兼容压缩历史消息、旧 `fileList/imageList` 去重及缺失图片MIME；旧数据无法还原的混选顺序不猜测。云端图片缺少已展开URL时按现有文件接口延迟查询。没有修改上传/解析服务、文件限额、模型输入图片、OCR或上下文预算。

## 从实操反向修正

1. 裁成正方形会遮住合成图左边的信息，改为固定外框内完整适配；提高图片规则的选择器优先级，避免冷启动CSS顺序覆盖。
2. 文件的原设备长说明挤压名称与大小，正常状态改为“本机文件”；不可用原因保留并可查看完整提示。
3. 滚动按钮放到轨道两侧，避免覆盖图片，只有溢出时出现；边界使用真实button禁用状态，保持键盘焦点。
4. 空编辑器序列化数据不能等同于有正文，新增展示判定，同时保留图片装饰、列表、表格等有效富文本。
5. DevTools实际捕获本机文档预览通过远程 `device.getLocalFilePreview` 返回403，原因为工作目录未获远程workspace授权。附件IPC已先验证设备与引用；预览入口不再传远程deviceId，使用既有本机预览协议。修正后真实显示TXT内容，未放宽服务端workspace校验，也未授权新目录。

本次开发环境深层页面执行Cmd+R曾出现空白壳，重启源码Electron后从首页进入同一话题恢复正常。未将一次开发壳重载异常归因于附件布局，也未修改应用路由或协议。
