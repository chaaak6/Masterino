## Failures found and corrections

- The first environment-discovery BDD received literal `{{pythonEnvironment}}`. Desktop app-state initialization had no caller, and the client placeholder registry lacked the variable. Both were fixed after failing regression tests; the rebuilt package passed discovery.
- Choosing the interpreter originally depended entirely on model instructions. Desktop shell execution now prepends the verified bundle directory to the child PATH; a real shared-runner test verifies the rest of PATH remains usable. The final app passed a bare `python` command without a supplied path.
- Post-execution signature verification found Python rewriting sealed bytecode caches after package relocation. Health/build probes now use `-B`; desktop command execution sets `PYTHONDONTWRITEBYTECODE=1`, and injected examples include `-B`. Regression tests failed before the change and passed afterward. The rebuilt app passed real command execution and strict signature verification.
- The initial complex report had visually related shapes but no actual GROUP, and included an invented survey sample size. Independent verification rejected it. The agent corrected its own script, added a real group and removed unsupported facts; the revised file passed.
- GLM-5.3-Flash complex authoring twice spent approximately 295 seconds thinking and ended without a tool call. The code's existing model-request total timeout is 300 seconds. Qwen3.7 Plus completed the actual tool workflow. The global timeout and unrelated model modules were not changed.
- One Qwen follow-up hit a visible upstream `network error`; regenerating completed the same edit/negative scenarios. This was not counted as an initial success.
- Windows test-package verification initially looked for desktop-config under `resources`; Windows ships it next to the executable. The assertion was corrected and the next package build passed.
