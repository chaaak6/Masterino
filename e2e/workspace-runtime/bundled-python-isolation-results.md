## Failures and corrections

- The model's initial PATH report mistakenly classified Resources/bin as the Python directory. Its actual PATH did not contain python-runtime; the detector was corrected and rerun.
- The first rich-PPT script used an incorrect rounded-rectangle enum. The agent corrected it and regenerated successfully; no application change was necessary.
- Two model gateway responses failed with `503 system_cpu_overloaded`. Earlier parallel calls showed UI result counts while the model claimed no content; their relationship to the overload was not established. A separate serial search succeeded. This does not prove parallel search reliability.
- The cancellation case found a genuine command-manager bug: only the shell was stopped, leaving the Python process. Two new real subprocess tests first reproduced the error, then passed after isolated POSIX process groups and Windows taskkill /T were added. They also verify an unrelated command survives. Registry behavior after kill is unchanged: getCommandOutput on the removed shell_id reports an error; the retest checks the process and delayed marker directly.
- Windows CI then exposed CMD quote escaping that prevented a quoted executable from starting. The runner now uses verbatim CMD arguments and the standard /d /s /c wrapping. Windows CI runs the real descendant-cancellation tests with an explicitly quoted executable and a script path containing spaces.
- A test-only formula-probe cleanup was flagged by existing App safety rules. It was declined and the probe file retained; no rules were bypassed or modified.

## Packaging and limits

The macOS test App is retained under `apps/desktop/release/python-final/mac-arm64/Masterino.app`. The earlier cancellation retest used `release/process-tree/`, and only Windows command quoting changed afterward. A read-only mounted DMG started its packaged interpreter with PATH limited to `/usr/bin:/bin`; all four actual Python integration tests passed. The test-only installer configuration points to mlai-test. Windows package and cancellation results must be checked on the latest PR CI run; Windows UI acceptance remains for a user machine.

The original report `bundled-python-presentation-results.md` describes the earlier revision; its bare-python/PATH behavior is superseded. Current guidance uses an absolute interpreter with `-I -B -X utf8` and project venvs. This guidance is not a sandbox that prevents arbitrary scripts from writing files. python-pptx still does not render slides or guarantee arbitrary SmartArt/OLE/animation round-trip fidelity. Native PowerPoint rendering and cross-platform font appearance have not been verified here.
